# Lean Context Engine (LCE) — Foundation Design

**Date:** 2026-06-09
**Status:** Approved (pending final spec review)
**Scope of this spec:** Environment setup + project scaffold for the LCE experiment.

## 1. Goal

Stand up the foundation for the LCE experiment: a local-SLM harness that
empirically compares **Naive RAG** (raw text chunks) against **Lean mode**
(AST skeletons + strict grammar harnessing), measuring token savings (>80%
target), format reliability, and sub-second latency on consumer hardware
(16GB RAM, RTX 3050 6GB VRAM, EndeavourOS/Arch, CUDA).

This session delivers: a working environment (uv, CUDA-compiled
llama-cpp-python, model downloaded) and the full repo scaffold (module stubs
with real signatures, working telemetry schema, complete setup script),
verified by a smoke test that loads the model and logs one transaction.

## 2. Decisions Made

| Decision | Choice | Rationale |
|---|---|---|
| Session scope | Environment + scaffold | Ready to code the engine next session |
| Env manager | `uv` (pyproject.toml + committed `uv.lock`) | Reproducibility is a project goal; handles CMAKE_ARGS builds |
| Primary model | Qwen2.5-3B-Instruct Q4_K_M (~2.1GB GGUF) | Leaves ~3.5GB VRAM for KV cache; strong structured output; safest path to sub-second TTFT |
| AST scope | Python only, stdlib `ast` | Zero extra deps; LCE's own codebase is the first test corpus (dogfooding) |
| Architecture | Single `lce/` package, one module per pipeline stage | Simple, testable in isolation, easy to evolve |
| Embeddings | ChromaDB default (all-MiniLM-L6-v2, ONNX, **CPU-only**) | All 6GB VRAM reserved for SLM weights + KV cache; embedding cost is CPU time, not a confound in inference latency |
| CLI | Typer | Thin, typed, autogenerated help |
| Benchmark arms | **Three**: naive / lean-prompt-only / lean+grammar | With grammar active, Format_Success is trivially 1 at the sampler level; the lean-prompt-only arm keeps the KPI meaningful |

## 4. Architecture & Data Flow

Two paths share one entry point:

**Indexing** — `lce index <path>` walks a target directory. Python files go
through `ast_skeleton.py` (signatures + docstring first-lines, bodies
discarded); Markdown files through `markdown_meta.py` (headers, frontmatter,
section summaries). Both **raw chunks** (Naive mode) and **skeletons** (Lean
mode) are embedded into **two separate ChromaDB collections** from identical
source material, so every query can hit either mode — this is what makes the
A/B comparison fair.

**Query** — `lce ask "<query>" --mode naive|lean [--grammar/--no-grammar]`
embeds the query (CPU), retrieves top-k from the corresponding collection,
builds the prompt (raw chunks for naive; signatures + strict harness
preamble for lean), and calls `engine.py`. With the grammar enabled, the
engine attaches `router.gbnf` so llama.cpp constrained decoding makes
non-conforming output impossible at the sampler level.

**Telemetry** — every engine call is wrapped by a `telemetry.py` context
manager that writes one row per transaction to `experiment_logs.db`.

**Benchmark** — `lce bench` (backed by `tests/benchmark_suite.py`) runs a
fixed query battery through all three arms under a single `run_id` and
prints the comparison table.

## 5. Telemetry Schema

`experiment_logs.db`, table `transactions` (SQLite, WAL mode, best-effort
writes — telemetry failure never kills an inference run):

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | |
| `run_id` | TEXT | groups a benchmark batch |
| `ts` | TEXT | ISO-8601 |
| `mode` | TEXT | `naive` \| `lean` \| `lean_grammar` |
| `model` | TEXT | GGUF filename |
| `query` | TEXT | |
| `prompt_tokens` | INTEGER | from llama.cpp usage stats, not estimated |
| `completion_tokens` | INTEGER | from llama.cpp usage stats |
| `ttft_ms` | REAL | streaming first-token timestamp |
| `total_latency_ms` | REAL | |
| `format_success` | INTEGER | 0/1 — output parses against the routing schema |
| `response` | TEXT | raw output, kept to audit format_success judgments |

## 6. Environment Setup (`scripts/setup_env.sh`)

Idempotent; in order:

1. **Baseline audit** — `nvidia-smi` (driver/CUDA versions, free VRAM), free
   RAM, Python version; logged so each "coding in public" post can cite the
   real environment.
2. **Install `uv`** if absent.
3. **`CMAKE_ARGS="-DGGML_CUDA=on" uv sync`** — compiles llama-cpp-python
   against cuBLAS.
4. **Model download** — `Qwen2.5-3B-Instruct-Q4_K_M.gguf` into `models/` via
   `huggingface_hub`; skipped if already present.

Dependencies (deliberately thin): `llama-cpp-python`, `chromadb`, `typer`,
`huggingface_hub`, `pytest` (dev).

## 7. Testing

Two tiers:

- **Unit (no GPU, CI-able):** AST extractor against fixture files, Markdown
  metadata extraction, telemetry writes to a temp DB, GBNF grammar validity.
- **Benchmark (`@pytest.mark.gpu`):** N fixed queries × 3 arms under one
  `run_id`; reports mean prompt tokens, % token savings vs naive, TTFT,
  total latency, and format-success rate per arm.

Smoke test for this session: load the model, produce one logged transaction.

## 8. Error Handling

- **Model load failure (VRAM exhaustion):** clear message suggesting an
  `n_gpu_layers` fallback, never a raw CUDA traceback.
- **Indexer:** skips unparseable files with a warning and a summary count;
  never aborts the walk.
- **Format validation:** a malformed model response is *data*
  (`format_success = 0`), never an exception.
- **Telemetry:** WAL mode, best-effort; failures logged to stderr only.

## 9. Out of Scope (this spec)

GUIs, cloud LLM APIs, multimedia indexing (per the baseline doc); also
multi-language AST (tree-sitter), GPU embeddings, and the actual
implementation of the pipeline logic — module bodies are stubs after this
session, to be implemented in the next phase via a written plan.
